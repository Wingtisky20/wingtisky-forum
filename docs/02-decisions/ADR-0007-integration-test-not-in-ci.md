# ADR-0007: 集成测试不在 CI 中运行

- **状态**：已接受
- **日期**：2026-09-13
- **决策者**：Wingtisky（决策） / Claude（建议）

## 背景

测试策略要求集成测试走**真实中间件**——Service 层真的读写 MySQL、Redis、Kafka、ES（spec §7）。

而社区的标准做法是 **Testcontainers**：测试启动时临时拉起真实的中间件容器，跑完销毁。它同时解决了"测的是真东西"和"环境可复现"两个问题。

但本机**没有 Docker**（ADR-0004）。于是产生一个必须正面回答的问题：**集成测试跑在哪？**

## 候选方案

### 方案 A：集成测试连本机已装中间件，只在本地跑（**选中**）
用 `@Tag("integration")` 把集成测试与单元测试隔离，CI 只跑单元测试。

- 优点：**测的是真实中间件**——Lua 脚本、ES 查询、Kafka 消费语义都能被覆盖
- 缺点：CI 里没有集成测试；PR 的绿灯不代表集成链路是好的

### 方案 B：Testcontainers
- 优点：行业标准；CI 里也能跑（GitHub Actions runner 自带 Docker）
- 缺点：**本机无 Docker，跑不了**——这是硬性阻断，不是偏好问题

### 方案 C：用内存替身（H2 代替 MySQL、Embedded Redis 等）
- 优点：不依赖任何外部进程，本地和 CI 都能跑，测试快
- 缺点：**测的不是真东西**，具体危害见下

## 决定

采用**方案 A**：集成测试连本机中间件（独立 test 库 / 索引），用 `@Tag("integration")` 标记，**只在本地运行，不进 CI**。

## 理由

**方案 C 是本 ADR 里最值得讲的部分——为什么不选它。**

内存替身看起来"解决了问题"，实际上是把测试变成了**验证剧场**（spec §9 闸门 2）：

- **H2 与 MySQL 的差异是真实的陷阱**：方言、隔离级别、`LIMIT` 语义、索引行为都不同。本项目 M6 的亮点恰恰是**深翻页的执行计划**——用 H2 测出来的 `EXPLAIN` 毫无意义
- **Embedded Redis 覆盖不了 Lua 脚本的语义**：秒杀的核心库存扣减写在 Lua 里（亮点 6），拿一个简化实现代替 Redis，等于**把最该测的那部分绕过去了**
- **最坏的结果是"测试全绿但线上失败"**：那比没有测试更糟，因为它给了虚假的信心

**宁可"集成测试只在本地跑"，也不要"测试看起来绿了但没测到真东西"。** 这条取舍和本项目整体的态度一致：宁可承认限制，也不制造证据。

**不进 CI 不是"懒得配"，是被环境逼出来的**：CI runner 上确实有 Docker，但如果只有 CI 能跑集成测试，就会出现"**CI 失败而本地复现不了**"的困境——本机没 Docker，你没法在本地把那个容器拉起来调试。一个你无法复现失败的测试，维护成本会高到没人看。

## 后果

- **正面**：集成测试测的是真实中间件，Lua / ES / Kafka 这些真东西能被覆盖；测试可信
- **负面**：
  - **CI 里只有单元测试**，绿色 CI **不等于**集成链路是好的。这一点必须显式写进 README 与 PR 模板，否则每个看到绿灯的人都会误以为全部通过
  - 集成测试依赖开发机的中间件状态（数据残留、端口占用），只能本地手动跑，无法自动化回归
  - 需要约定：集成测试连**独立的 test 库/索引**，不污染开发数据

## 被否决方案为何不选

- **方案 B（Testcontainers）**：**这是当前的标准做法，本项目用不了**——本机无 Docker。结论不是因为不认可，而是环境不支持
- **方案 C（内存替身）**：理由见上。核心是"**不要用假的中间件去测一个以中间件为卖点的项目**"

## 如果有 Docker，应该怎么做

本节是给面试官看的"我知道标准做法是什么"：

1. 引入 Testcontainers 的 MySQL / Redis / Kafka / Elasticsearch 模块；Kafka 用 KRaft 模式（不带 ZooKeeper）
2. 把 `@Tag("integration")` 的测试改为**由环境变量决定是否运行**（例如 `IT=true`），本地与 CI 都能跑
3. 用 `@DynamicPropertySource` 把容器的随机端口注入 Spring 配置，避免端口冲突
4. ES 镜像需要预装 IK 分词器——用自定义 `Dockerfile` 或启动后安装插件，这一步在 Testcontainers 里略麻烦，是主要成本

## 遗留问题：评估时点待定

- §7.2 写的是"**M7** 可评估"
