## 3. 业务域

```
内容域 forum     用户/认证 · 帖子 · 评论 · 专栏 · 检索 · 通知
交易域 trade     商品（付费专栏/课程）· 订单 · 支付（模拟）· 内容解锁
秒杀域 seckill   优惠券库存 · Lua 扣减 · 异步下单 · 防刷
```

**闭环**：写帖子/专栏 → 专栏设为付费 → 上架为商品 → 发券 → 秒杀抢券 → 创建订单 → 支付 → 解锁内容 → 回到内容域。

## 4. 八个必须落地的亮点

| # | 亮点 | 所属 |
|---|---|---|
| 1 | 高频读：Caffeine → Redis → MySQL + Pub/Sub 跨节点失效 + Redisson 防击穿 | forum |
| 2 | 异步写：Kafka 自定义分区 + 手动 Ack + Redis 幂等 | 共用 |
| 3 | 检索：ES + 增量/全量同步 + IK 扩展 | forum |
| 4 | DB 治理：Deferred Join 深翻页 | forum / trade |
| 5 | 安全限流：Spring Security RBAC + Redis ZSet 滑动窗口 | gateway / forum |
| 6 | 秒杀一致性：Lua 原子扣减 + 异步下单 + 库存回补 | seckill |
| 7 | 分布式锁：Redisson 跨实例互斥 | seckill |
| 8 | 最终一致性：本地消息表 + 定时对账 | trade / seckill |

**秒杀是收口**——亮点 1、2、4、5 在它身上从"各自成立的技术点"变成"一个系统里互相咬合的部件"。

## 6. 明确不做的事（YAGNI）

**这份清单与"要做什么"同等重要，它会在每次"要不要加个功能"的讨论中被引用。**

- ❌ **全套微服务**（网关 + 注册中心 + Sentinel + Seata 全家桶）—— 只按**故障域**拆 3 个服务
- ❌ **Sentinel** —— **它会抢戏**：限流亮点是自己实现的 ZSet 滑动窗口，换成 Sentinel 就变成"调了个 API"
- ❌ **Seata** —— 用本地消息表 + 最终一致；2PC 的同步阻塞与秒杀削峰目标冲突
- ❌ **RocketMQ** —— 已有 Kafka，换中间件没有收益只有学习成本
- ❌ **Docker**（本地）—— 本机无 Docker、Win10 Home 无 WSL2
- ❌ **分库分表** —— 本地单机、数据量不支持；且做了分表就无法讲 Deferred Join，自相矛盾
- ❌ 自建对象存储（图片走本地存储 + 预留接口）
- ❌ 推荐算法（首页用 时间 + 热度分）
- ❌ IM 长连接（私信做拉取式基础版）
- ❌ 多级审核工作流、复杂权限矩阵
- ❌ 全量 DDD 落地（领域事件、聚合根全套）
- ❌ Kafka Streams / Flink 流处理
- ❌ 公网部署 —— GitHub 公开 + 本地可复现
- ❌ **关键：不做"业务域拼贴"**（如"二手交易 + 校园趣事 + 论坛"）。判据是**域之间有无真实数据流转**，不是"技术含量高不高"
