## 关键决策与理由

| 决策 | 为什么 | 记录 |
|---|---|---|
| 持久层用 **MyBatis 不用 Plus** | M6 的深翻页亮点要手写 SQL，Plus 会把这个亮点绕开——用它的代价不是"性能差一点"，是**把最大的亮点关掉了** | ADR-0012 |
| 认证用 **JWT 双令牌**，可撤销性放在刷新令牌上 | 不跟"JWT 不能撤回"这个固有矛盾硬碰：access 保持无状态**零查询**、30 分钟短命；refresh 存 Redis 可删。**正常请求不查任何存储**——这正是 ADR-0010 拆分服务能简化的前提 | ADR-0013 |
| 令牌里**只存 jti 不存令牌串** | 令牌串等于凭据，存进 Redis 会让"Redis 泄露"直接等于"账号被盗" | ADR-0013 |
| 刷新时**轮换** | 不轮换的话一张 refresh 能连用 7 天，泄露后攻击者可无限续期而用户毫无察觉 | ADR-0013 |
| 限流降级**按接口分类** | 普通接口 fail-open；**登录接口降级到本地内存**——因为那个限流的唯一目的就是防撞库，放行等于把门打开 | ADR-0014 |
| **`/users/me` 改成 `/users/{id}`** | `/me` 没有资源标识，归属校验永远不会失败，**等于没写** | 设计稿 §7 |
| 登录失败**不区分"用户不存在"与"密码错误"** | 否则接口变成用户名探测器 | `UserService.authenticate` |

```bash
#    限流：连打 11 次登录 —— 前 10 次应 401，第 11 次起 429
for i in $(seq 1 11); do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST localhost:8080/api/auth/login \
    -H 'Content-Type: application/json' -d '{"username":"x","password":"yyyyyyyy"}'
done
#    ⚠️ 前 10 次是 401 而不是 429 才是关键——一个永远返回 429 的系统也能"通过"
```

## 踩过的坑

M1 的坑比 M0 密集，而且**几乎全是"只有真跑才暴露"的类型**。按教训排：

| 坑 | 为什么编译期和单测都发现不了 |
|---|---|
| **`provided` 作用域的前提是"运行时真的有人提供"** | 我标了 `provided` 但当时没人提供 → 应用一启动就 `NoClassDefFoundError`。编译能过、单测能过（单测不扫组件），**只有真启动才暴露** |
| **`characterEncoding=utf8mb4` 是错的** | 那参数要的是 Java 字符集名（`UTF-8`），`utf8mb4` 是 MySQL 的叫法 |
| **mysql 客户端默认 GBK 把中文写坏** | 脚本退出码 0、没有任何报错，数据却是坏的，且 `?` 不可恢复 |
| **日志里中文 grep 不到** | Java 17 在中文 Windows 按 GBK 写控制台。**我一度以为"降级代码根本没执行"**，实际打了 15 条 |
| **Maven 的 `-D` 覆盖不动 POM 里的字面量** | 失败模式是**静默的成功**：参数没生效、测试一个没跑，却显示 `BUILD SUCCESS` |
| **`-pl` 不带 `-am` 会解析到本地仓库的旧版本** | 同一根因**第三次**咬人（前两次：CI 首跑的 check-deps、dependency:tree）。已固化成规则 |
| **请求体非法 JSON 返回 500** | 请求体问题应返 400。500 会让监控把"有人发了畸形请求"统计成"服务端出错" |
| **滑动窗口的边界测试第一版是错的** | 把 Lua 里清理窗口的步骤整行删掉，它照样全绿——因为 `PEXPIRE` 让 key 过期，计数自然归零。**是反证发现了它根本没在测滑动** |

> **最后一条值得单说。** 反证（故意破坏实现，看测试会不会失败）不是为了"证明测试好"，
> 而是为了发现**测试其实没在测它声称的东西**。第一版边界测试看起来完全合理，
> 只有反证能戳穿它。

## 遗留与风险

| 项 | 说明 |
|---|---|
| **限流的"按用户名"维度未实现** | 设计 §5.4 原本要求登录同时按 IP 与用户名限。**这是有意留的缺口**（用户名在请求体里，拦截器读它需要请求包装器），理由与建议做法写在设计稿 |
| **注销后旧 access 仍有效，最长 30 分钟** | ADR-0013 明确接受的代价，**已实测确认这个窗口真实存在**（不是推断） |
| **角色变更最长 30 分钟生效** | 同上，也实测过：撤销 ADMIN 后用旧令牌访问仍是 200，重新登录才 403 |
| **本地内存兜底在 M9 后失效** | 多实例时每个实例各限一份（N 倍）。届时要么给 Redis 上哨兵，要么登录改 fail-closed。已记入 ADR-0014 |
| **本机 Maven 仓库仍残留旧架构模块** | 不影响构建，属陈旧状态 |
| **`README.md` 仍缺「本地运行」一节** | 等 M2 前端起来后一并补 |
