## 关键决策与理由

| 决策 | 为什么 | 记录 |
|---|---|---|
| 业务域从纯论坛扩展为「技术社区 + 付费内容」 | 判据是**域之间有无真实数据流转**，不是技术含量高不高 | ADR-0009 |
| 拆 3 个服务，且**先画逻辑边界后做物理拆分** | 拆分理由是**故障域隔离**（不依赖流量大小，可实测）；不在未经验证的判断上押注 | ADR-0010 |
| 跨服务一致性用本地消息表 + 最终一致，**不用 Seata** | Seata 的同步阻塞与秒杀削峰目标直接冲突。**选型看场景，不看组件名气** | ADR-0011 |
| 合并方式用 **Merge commit 而非 Squash** | 你要的是"靠 commit 一步步看迭代"，Squash 会把过程压没 | ADR-0008 |
| `wip:` 提交**允许进 `main`**，但必须可编译 | 若要求"合并前整理掉"，等于把刚为保留过程而放弃的压平手工再做一遍——自相矛盾 | ADR-0008 |
| 前端走 **Element Plus 默认视觉**，不大量 AI 生图 | 省下的时间投给后端亮点 | spec §12 |
| **协作基建提前到 M0 第一步** | 新对话能否接手依赖它——它应该是第一步，不是第四步 | 本文件 |

## 踩过的坑

| 坑 | 根因 | 记录 |
|---|---|---|
| `gh` 能建仓库但 `git push` 连不上 | `api.github.com` 通、`github.com` 不通；git 未配代理 | troubleshooting.md |
| `mvn -pl app -am spring-boot:run` 跑不起来 | `-am` 把无 main class 的根聚合 POM 拽进 reactor | 计划全球约束 |
| `mvn clean compile` 后 `ls */target/*.jar` 失败 | **compile 不产 jar** | 计划全球约束 |
| 两个改动挤进同一个提交 | 同一文件的多处改动被一次 `git add` 全部暂存 | collaboration.md §5.3 |
| **决策改了，5 份文档没跟上** | 合并方式改 Merge commit 时只改了 spec §10.2，**每次对话自动加载的 `CLAUDE.md` 和必读的 `collaboration.md` 都还写着 Squash** | ADR-0008、commit `b990672` |

> **最后这条值得单说。** 决策落地时改的是"设计文档"，而真正会被下一个对话读到的是"入口文档"。两者不是同一批文件——`CLAUDE.md` 自动加载、`collaboration.md` 是会话协议必读，它们比 spec 更早被看到。**改决策时应该顺着"谁会读到它"倒推一遍要改哪些文件**，而不是只改做出决策的那一处。
